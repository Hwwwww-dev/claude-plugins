# /mnemosyne:save - 保存上下文

用户输入: $ARGUMENTS

> **核心原则**：像写工作日志一样记录会话，让未来的自己（或 Claude）能快速理解并继续工作

---

## 第一步：智能信息提取

**遍历整个对话历史，按以下规则提取信息：**

### 1.1 起点：用户意图 (Intent)

**提取规则**：
- 找到用户**第一条消息**，这通常包含核心意图
- 识别关键动词：「实现」「修复」「添加」「优化」「重构」「分析」「配置」
- 提取目标对象：功能名、模块名、文件名、错误描述
- 记录任何约束条件：「不要改动 X」「必须兼容 Y」「性能要求 Z」

**提取示例**：
```
用户消息: "帮我给登录页面添加记住密码功能，要用 localStorage 存储，不要用 cookie"

提取结果:
- 动作: 添加功能
- 目标: 登录页面 - 记住密码
- 技术约束: 使用 localStorage，禁用 cookie
```

### 1.2 过程：关键决策 (Decisions)

**提取规则**：
- 搜索对话中的**选择时刻**：
  - Claude 提供多个方案让用户选择
  - 用户明确表示「用 A 不用 B」
  - 讨论后确定的技术方案
- 记录**决策三要素**：
  - 决策点：在什么问题上做决策
  - 选择：最终选了什么
  - 理由：为什么这样选（用户说的或推断的）

**识别模式**：
```
模式1: "我建议用 X，因为..." + 用户同意
模式2: "你想用 A 还是 B？" + 用户选择
模式3: 用户直接说 "用 X 方案"
模式4: 讨论后说 "那就这样定了"
```

### 1.3 产出：代码变更 (Changes)

**提取规则**：
- 扫描所有 **Write/Edit 工具调用**，记录：
  - 文件路径（绝对路径转相对路径）
  - 操作类型：新建 / 修改 / 删除
  - 变更摘要：改了什么（不是完整代码）
- 扫描 **Bash 工具调用**，识别：
  - 安装的依赖：`npm install`、`pip install`
  - 执行的构建：`npm run build`、`cargo build`
  - 运行的测试：`npm test`、`pytest`

**输出格式**：
```
新建文件:
  - src/hooks/useRememberMe.ts (记住密码 Hook)
  - src/utils/storage.ts (localStorage 封装)

修改文件:
  - src/pages/Login.tsx (集成记住密码功能)
  - src/types/auth.ts (添加 RememberMeOptions 类型)

依赖变更:
  - 无新增依赖

执行命令:
  - npm run dev (启动开发服务器)
  - npm test (运行测试，全部通过)
```

### 1.4 状态：任务进度 (Progress)

**提取规则**：
- 识别**完成标志**：
  - Claude 说「已完成」「搞定了」「实现好了」
  - 测试通过的输出
  - 用户确认「可以了」「没问题」
- 识别**未完成标志**：
  - 「还需要」「待处理」「下一步」
  - 用户说「先这样」「之后再说」
  - 明确的 TODO 注释
- 识别**进行中标志**：
  - 「正在」「处理中」
  - 最后一条消息涉及的任务

**进度评估**：
```
完成度计算:
- 统计用户提出的所有需求点
- 统计已明确完成的需求点
- 完成度 = 已完成 / 总需求 × 100%
```

### 1.5 障碍：问题与解决 (Issues)

**提取规则**：
- 搜索**错误信号**：
  - 报错信息：`Error`、`Exception`、`Failed`
  - 用户反馈：「不行」「出错了」「有问题」
  - Claude 说：「发现问题」「需要修复」
- 记录**解决过程**：
  - 问题描述
  - 尝试的方案（包括失败的）
  - 最终解决方案
  - 当前状态：已解决 / 未解决 / 绕过

### 1.6 环境：技术上下文 (Tech Context)

**提取规则**：
- 从**文件扩展名**推断语言：`.ts` → TypeScript, `.py` → Python
- 从**导入语句**识别框架：`import React` → React, `from fastapi` → FastAPI
- 从**配置文件**提取信息：
  - `package.json` → Node.js 项目，依赖列表
  - `Cargo.toml` → Rust 项目
  - `pyproject.toml` → Python 项目
- 从**命令**识别工具：`npm` → npm, `pnpm` → pnpm, `cargo` → Cargo

### 1.7 地图：文件关联 (File Map)

**提取规则**：
- 列出所有**被读取的文件**（Read 工具）
- 列出所有**被修改的文件**（Write/Edit 工具）
- 分析**依赖关系**：
  - 从 import 语句提取
  - 标注核心文件 vs 辅助文件

**输出格式**：
```
核心文件 (直接修改):
  - src/pages/Login.tsx
  - src/hooks/useRememberMe.ts

关联文件 (被引用):
  - src/types/auth.ts
  - src/utils/storage.ts

依赖链:
  Login.tsx → useRememberMe.ts → storage.ts
```

### 1.8 路标：续作指引 (Continuation)

**提取规则**：
- 找到**最后的工作状态**：
  - 最后修改的文件
  - 最后执行的命令
  - 最后讨论的话题
- 提取**明确的下一步**：
  - 用户说「下次再做 X」
  - Claude 建议「接下来可以 Y」
  - 未完成的 TODO
- 生成**快速恢复指令**：
  - 需要先读取哪些文件
  - 需要先运行什么命令
  - 从哪里继续

### 1.9 会话统计 (Session Stats)

**提取规则**：
- 统计**会话规模**：
  - 用户消息总数
  - Claude 回复总数
  - 对话轮次（来回次数）
- 统计**工具使用**：
  - Read 工具调用次数（读取了多少文件）
  - Write 工具调用次数（新建了多少文件）
  - Edit 工具调用次数（修改了多少文件）
  - Bash 工具调用次数（执行了多少命令）
  - Grep/Glob 工具调用次数（搜索次数）
  - Task 工具调用次数（启动了多少 subagents）
- 估算**会话时长**：
  - 从第一条消息到最后一条消息的时间跨度
  - 标注主要活跃时段

**输出格式**：
```
对话规模:
  - 用户消息: 15 条
  - Claude 回复: 18 条
  - 对话轮次: 15 轮

工具使用:
  - 文件读取: 12 次
  - 文件修改: 5 次 (2 新建, 3 编辑)
  - 命令执行: 8 次
  - 代码搜索: 6 次
  - Subagents: 2 次

会话时长: 约 45 分钟 (14:30 - 15:15)
```

### 1.10 代码质量分析 (Code Quality)

**提取规则**：
- 统计**代码变更规模**：
  - 总新增行数（所有 Write/Edit 的累计）
  - 总删除行数（Edit 操作中的删除）
  - 净变化行数（新增 - 删除）
- 检测**质量指标**：
  - Linting 检查结果（如果有运行 eslint/pylint）
  - 类型检查结果（如果有运行 tsc/mypy）
  - 测试覆盖率变化（如果有测试报告）
- 识别**代码风格**：
  - 是否遵循项目现有风格
  - 是否添加了注释/文档
  - 是否有 TODO/FIXME 标记

**输出格式**：
```
代码规模:
  - 新增: +356 行
  - 删除: -42 行
  - 净增: +314 行

  - ✅ 遵循 Prettier 格式
  - ✅ 添加了 JSDoc 注释
  - ⚠️ 包含 2 个 TODO 标记
```

### 1.11 关键代码片段 (Code Snippets)

**提取规则**：
- 识别**核心代码**：
  - 新增的核心函数/类（通常是 Write 工具创建的）
  - 重要的修改片段（Edit 工具修改的关键逻辑）
  - 复杂的算法或业务逻辑
- 保存**精简版本**：
  - 只保留函数签名和关键逻辑
  - 移除过长的实现细节
  - 最多保留 3-5 个最重要的片段
- 标注**上下文**：
  - 文件位置
  - 用途说明
  - 与其他代码的关系

**输出格式**：

### 1.15 影响分析 (Impact Analysis)

**提取规则**：
- 分析**影响范围**：
  - 直接修改的模块
  - 间接影响的模块（通过依赖关系）
  - 可能受影响的功能点
- 评估**风险等级**：
  - 🟢 低风险：纯新增功能，无破坏性
  - 🟡 中风险：修改现有代码，需回归测试
  - 🔴 高风险：核心逻辑变更，影响多个模块
- 提出**测试建议**：
  - 需要测试的场景
  - 需要关注的边界条件
  - 建议的回归测试范围

```

  - 引入了新的存储机制
  - 需要考虑隐私安全

测试建议:

  - ⚠️ 手动测试：跨浏览器兼容性
```
