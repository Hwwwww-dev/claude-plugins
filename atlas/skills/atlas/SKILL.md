# Atlas 任务编排框架使用指南

你正在阅读 Atlas Skill,这是一个强大的任务协调和并发执行框架。

## 何时使用 Atlas

**核心场景**：多文件批量操作、项目级变更、复杂组合任务

**典型触发词**：
- 批量操作: "所有"、"批量"、"全部"、"每个"
- 项目级别: "整个项目"、"项目级"、"全局"、"重构模块"
- 组合任务: "分析并..."、"先...再..."、"然后"
- 多步骤: "步骤"、"阶段"、"依次"
- 大规模: "大量"、"很多"、"整个目录"

**示例场景**：
- 给所有组件添加类型定义
- 重构整个模块的架构
- 分析性能问题并优化
- 批量更新 import 路径
- 分阶段迁移到新框架

**为什么用 Atlas**：并行处理多个文件，智能分解复杂任务，显著提升效率

## 如何使用 Atlas

### 方式1: 自动触发(推荐)

当你识别到上述场景,**自动**按以下流程操作:

#### 步骤1: 调用 atlas-coordinator

首先调用 `atlas-coordinator` agent 生成执行计划:

```
请使用 atlas-coordinator agent 分析以下任务:
任务: [用户的任务描述]
项目路径: [当前工作目录]
```

atlas-coordinator 会返回一个 JSON 格式的执行计划。

#### 步骤2: 根据计划并发执行

拿到 coordinator 的计划后,根据 `parallel_strategy` 字段决定如何执行:

**如果 parallel_strategy = "parallel"**:
```
同时调用多个 atlas-executor agents:
- atlas-executor: 执行子任务1
- atlas-executor: 执行子任务2
- atlas-executor: 执行子任务3

一次性发起所有调用,实现并行执行。
```

**如果 parallel_strategy = "sequential"**:
```
依次调用 atlas-executor agents:
1. 先执行子任务1,等待完成
2. 再执行子任务2,等待完成
3. 最后执行子任务3
```

**如果 parallel_strategy = "mixed"**:
```
分阶段执行:
- 阶段1 (串行): 子任务1
- 阶段2 (并行): 子任务2, 3, 4
- 阶段3 (串行): 子任务5
```

#### 步骤3: 聚合结果

收集所有 executor 的返回结果,生成综合报告。

### 方式2: 建议用户使用命令

如果任务特别复杂或你不确定,可以建议用户使用 `/atlas` 命令:

```
这个任务适合使用 Atlas 框架来处理。你可以运行:

/atlas [任务描述]

例如:
/atlas 给所有组件添加 TypeScript 类型定义

Atlas 会自动分解任务并并行执行,速度更快。
```

## 重要原则

### ✅ 你应该做的

1. **主线程编排**: 你在主线程,负责调用 agents
2. **先调 coordinator**: 总是先让 coordinator 分析任务
3. **并行发起**: 可并行的 executor 一次性发起
4. **收集结果**: 聚合所有 executor 的结果
5. **清晰报告**: 向用户报告执行状况

### ❌ 你不应该做的

1. **不要让 skill 调用 agents**: Skill 只提供指导,实际调用由主线程完成
2. **不要自己执行任务**: 你不直接修改文件,由 executor 完成
3. **不要串行调用可并行任务**: 应一次性发起多个 executor
4. **不要跳过 coordinator**: 复杂任务必须先规划

## 完整工作流示例

### 示例1: 批量操作

```
用户: "给所有 API 添加错误处理"

步骤1: 调用 coordinator
└─→ atlas-coordinator
    返回计划: 15个文件, 分3组并行

步骤2: 并行执行
一次性调用:
├─→ atlas-executor: 处理文件 1-5
├─→ atlas-executor: 处理文件 6-10
└─→ atlas-executor: 处理文件 11-15

步骤3: 报告结果
✅ 成功: 14/15
❌ 失败: 1/15 (需人工处理)
```

### 示例2: 有依赖的任务

```
用户: "先提取公共逻辑,再更新所有调用"

步骤1: 调用 coordinator
└─→ atlas-coordinator
    返回计划: mixed 策略, 2个阶段

步骤2: 分阶段执行
阶段1 (串行):
└─→ atlas-executor: 提取公共逻辑

阶段2 (并行):
├─→ atlas-executor: 更新文件1
├─→ atlas-executor: 更新文件2
└─→ atlas-executor: 更新文件3

步骤3: 报告
✅ 提取成功, 所有调用已更新
```

## 不适合使用 Atlas 的场景

- ❌ **单文件修改**: 直接用 Read + Edit
- ❌ **需要人工决策**: 架构设计、方案选型等
- ❌ **外部工具操作**: 编译、部署、测试等用 Bash

## 关键原则

### 角色分工
- **coordinator**: 只规划不执行 - 分析任务、分解子任务、生成计划
- **executor**: 只执行不规划 - 执行子任务、修改文件、报告结果
- **你(主线程)**: 负责编排 - 识别场景、调用agents、聚合结果

### 并行执行
```
✅ 正确: 一次性发起所有可并行的 executor
❌ 错误: 逐个调用 executor 等待完成
```

### 性能建议
- 合理分组 (3-5个 executor 为佳)
- 平衡负载 (每组工作量相近)
- 超过10个子任务时分批执行

---

**记住: Atlas 是任务执行引擎,不是任务规划工具。先规划(coordinator),再执行(executor),最后聚合(你)。**
