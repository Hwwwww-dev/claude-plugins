# Implement Feature - 功能实现工作流

你正在使用 Implement Skill，这是一个完整的功能实现工作流框架。

## 何时使用

当用户需要**实现新功能或需求**时使用，例如：
- "实现用户认证功能"
- "添加数据导出功能"
- "开发实时通知系统"
- "创建新的 Dashboard 页面"

## 工作流程

### 第1步: 需求理解

明确用户的实现需求：
- 功能目标是什么？
- 涉及哪些模块？
- 有什么特殊要求？

### 第2步: 分析阶段

**选择性调用相关分析 agents**（不要全部调用）：

- **code-analyzer**: 了解现有代码质量和规范
- **architecture-analyzer**: 涉及架构调整时使用（推荐）
- **security-scanner**: 涉及认证、数据处理时使用（推荐）
- **performance-analyzer**: 有性能要求时使用

### 第3步: 规划阶段

调用 atlas-coordinator agent 生成实现计划：

```
调用 atlas-coordinator agent:

任务: 实现 [功能描述]

上下文:
- 分析结果: [分析 agents 的关键发现]
- 现有架构: [架构信息]
- 约束条件: [安全、性能等要求]

请生成详细的实现计划，包括：
- 需要创建/修改的文件
- 实现步骤和依赖关系
- 并行执行策略
```

### 第4步: 执行阶段

根据 coordinator 的计划调用 atlas-executor：
- **并行**: 一次性发起所有可并行的 executor
- **串行**: 按顺序执行有依赖关系的任务

### 第5步: 验证和总结

生成实现报告，包含：
- 实现概况 (成功/失败统计)
- 文件变更 (新增/修改列表)
- 关键实现要点
- 注意事项和后续建议

## 完整示例

```
用户: "实现基于 JWT 的用户认证功能"

【步骤1】需求理解
- 功能: JWT 认证
- 涉及: 登录、注册、Token 管理

【步骤2】分析
- architecture-analyzer: 了解现有架构
- security-scanner: 检查安全措施

【步骤3】规划
调用 atlas-coordinator 返回计划:
- 子任务1: 创建 JWT 工具类
- 子任务2-4: 实现 API 和中间件
- 策略: mixed (1串行，2-4并行)

【步骤4】执行
阶段1: executor 创建工具类
阶段2: 3个 executor 并行实现 API

【步骤5】报告
生成实现报告和注意事项
```

## 关键原则

### ✅ 必须做到
- 按流程执行: 分析 → 规划 → 执行
- 选择性分析: 只调用需要的 analyzer
- 主线程编排: 你负责调用所有 agents
- 充分并行: 尽可能并行执行

### ❌ 禁止操作
- 不要跳过规划 (必须先调用 coordinator)
- 不要让 agents 互调
- 不要盲目分析所有维度
- 不要串行执行可并行任务

## 灵活调整

根据任务复杂度选择：
- **简单**: 跳过分析，直接规划执行
- **中等**: 1-2个 analyzer + 规划执行
- **复杂**: 多维度分析 + 详细规划 + 分阶段执行
