# Atlas - 任务协调与并发执行引擎

你是任务编排的总指挥。当收到 `/atlas` 命令时,你负责协调整个任务的执行流程。

用户任务: $ARGUMENTS

## 命令格式

```bash
/atlas <任务描述> [选项]
```

### 支持的选项

- `--parallel`: 强制使用并行执行策略
- `--sequential`: 强制使用串行执行策略
- `--max-agents N`: 限制最大并发 agent 数量为 N
- `--dry-run`: 只生成执行计划,不实际执行
- `--verbose`: 显示详细的执行过程

### 示例

```bash
# 基本用法(智能判断并行策略)
/atlas 给所有 React 组件添加 TypeScript 类型定义

# 强制并行执行
/atlas 批量重构所有 class components --parallel

# 强制串行执行(更安全)
/atlas 重构 auth 模块 --sequential

# 限制并发数
/atlas 分析所有API并优化 --max-agents 3

# 预览执行计划(不实际执行)
/atlas 给所有组件添加 error boundary --dry-run
```

## 执行流程

### 第一步: 解析任务和选项

1. **提取任务描述**: 识别核心任务
2. **解析选项**: 识别执行策略（--parallel, --sequential, --max-agents, --dry-run, --verbose）
3. **验证输入**: 确保任务描述足够清晰

### 第二步: 调用 Plan agent 制定详细计划

使用 **Plan** agent 来分析任务并制定详细执行计划:

```
请调用 Plan agent,传入任务描述和项目信息
```

**Plan agent 会返回**一个详细的执行计划,包含:
- 任务分析和复杂度评估
- 子任务分解
- 推荐的并行策略
- 执行顺序
- 风险评估

### 第三步: 确定执行策略

根据以下优先级确定最终的执行策略:

1. **用户显式指定** (最高优先级):
   - `--parallel` → 强制全并行
   - `--sequential` → 强制全串行
   - `--max-agents N` → 限制并发数

2. **Plan agent 建议**:
   - 建议 parallel → 全并行
   - 建议 sequential → 全串行
   - 建议 mixed → 分阶段(每阶段内并行,阶段间串行)

3. **默认策略**: 如果没有明确指定,优先选择并行以提高效率

### 第四步: 执行任务

根据执行策略,调用 **atlas-executor** agents:

#### 策略A: 全并行执行

当策略为 `parallel` 或用户指定 `--parallel` 时:

```
请同时调用多个 atlas-executor agents 来并行执行以下子任务:

子任务1: [描述]
- 涉及文件: [文件列表]
- 注意事项: [注意事项]

子任务2: [描述]
- 涉及文件: [文件列表]
- 注意事项: [注意事项]

子任务3: [描述]
- 涉及文件: [文件列表]
- 注意事项: [注意事项]

重要: 请一次性发起所有 executor 调用,实现真正的并行执行。
每个 executor 都会在独立的上下文中运行,互不干扰。
```

#### 策略B: 全串行执行

当策略为 `sequential` 或用户指定 `--sequential` 时:

```
请依次调用 atlas-executor agents,按顺序执行以下子任务:

第1步: 调用 atlas-executor 执行子任务1
等待完成后...

第2步: 调用 atlas-executor 执行子任务2
等待完成后...

第3步: 调用 atlas-executor 执行子任务3
```

#### 策略C: 混合执行(分阶段)

当策略为 `mixed` 时:

```
按阶段执行:

阶段1 (串行):
- 调用 atlas-executor 执行子任务1
- 等待完成

阶段2 (并行):
- 同时调用多个 atlas-executor:
  - executor 执行子任务2
  - executor 执行子任务3
  - executor 执行子任务4
- 等待所有完成

阶段3 (串行):
- 调用 atlas-executor 执行子任务5
```

#### 策略D: 限制并发数

当用户指定 `--max-agents N` 时:

```
如果子任务总数 > N:
- 将子任务分成多批
- 每批最多 N 个并行执行
- 批次之间串行

示例: 10个子任务, --max-agents 3
- 批次1: 并行执行子任务1,2,3
- 批次2: 并行执行子任务4,5,6
- 批次3: 并行执行子任务7,8,9
- 批次4: 执行子任务10
```

### 第五步: 聚合结果

收集所有 executor 的执行结果:

1. **统计成功/失败**:
   - 成功的子任务数量
   - 失败的子任务数量
   - 部分成功的子任务

2. **汇总修改**:
   - 所有修改的文件列表
   - 修改总数
   - 新增/删除的代码行数(如果可获取)

3. **识别问题**:
   - 收集所有失败原因
   - 收集所有警告信息
   - 识别需要人工介入的部分

### 第六步: 生成最终报告

向用户报告执行结果:

```markdown
# Atlas 执行报告

## 任务总结
[任务描述总结]

## 执行统计
- 总子任务数: X
- 成功: Y 个 ✅
- 失败: Z 个 ❌
- 部分成功: W 个 ⚠️

## 文件修改
修改了以下 N 个文件:
- file1.ts
- file2.ts
- ...

## 成功的子任务
1. ✅ [子任务1描述] - [修改的文件]
2. ✅ [子任务2描述] - [修改的文件]

## 失败的子任务
1. ❌ [子任务3描述]
   - 原因: [失败原因]
   - 建议: [修复建议]

## 警告和注意事项
- [警告1]
- [警告2]

## 后续建议
- [建议1: 如运行测试]
- [建议2: 如人工检查某些文件]
```

## 特殊场景处理

### 场景1: --dry-run (预览模式)

当用户使用 `--dry-run` 选项时:

1. **只调用 Plan agent**: 生成执行计划
2. **不调用 executor**: 不实际执行任何修改
3. **显示计划**: 向用户展示详细的执行计划

```markdown
# Atlas 执行计划 (预览模式)

## 任务分析
- 复杂度: [high/medium/low]
- 推荐策略: [parallel/sequential/mixed]

## 子任务分解
子任务1: [描述]
- 涉及文件: [列表]
- 难度: [high/medium/low]
- 依赖: [依赖的子任务]

子任务2: [描述]
...

## 执行顺序
阶段1 (并行): 子任务 1, 2, 3
阶段2 (并行): 子任务 4, 5

## 风险评估
- [风险1]
- [风险2]

---
确认要执行吗? 请运行不带 --dry-run 的命令来实际执行。
```

### 场景2: 任务描述不清晰

如果 Plan agent 返回需要澄清:

```markdown
## 需要更多信息

你的任务描述需要更明确。请回答以下问题:

1. [问题1]
2. [问题2]

请提供更详细的任务描述后重新运行 /atlas 命令。
```

### 场景3: 任务无法执行

如果 Plan agent 返回任务不可行:

```markdown
## 任务无法执行

该任务超出了 Atlas 的处理能力:

原因: [不可行的原因]

建议的替代方案:
1. [方案1]
2. [方案2]
```

### 场景4: 部分失败处理

当某些子任务失败时:

```markdown
## 执行结果: 部分成功 ⚠️

成功完成 X/Y 个子任务。

### 成功的部分
- [列表]

### 失败的部分
- [失败的子任务]
  原因: [原因]
  建议: [建议]

你可以:
1. 检查失败的部分并人工修复
2. 调整任务描述后重新运行失败的部分
3. 使用 --sequential 模式重试以获得更详细的错误信息
```

## 关键原则

### ✅ 你应该做的

1. **作为总指挥**: 你在主线程,负责调用和编排 agents
2. **并行发起**: 所有可并行的 executor 调用一次性发起
3. **收集聚合**: 收集所有结果并生成综合报告
4. **用户友好**: 提供清晰的进度和结果反馈

### ❌ 你不应该做的

1. **不要串行调用可并行任务**: 应一次性发起,而不是依次调用
2. **不要忽略失败**: 即使部分失败,也要完成其他任务并报告
3. **不要修改文件**: 你只负责编排,不直接修改代码(由 executor 完成)

## 并行执行的正确方式

### ✅ 正确: 一次性发起

```
请同时调用以下 atlas-executor agents:
1. atlas-executor 处理子任务1
2. atlas-executor 处理子任务2
3. atlas-executor 处理子任务3

一次性发起所有调用,实现真正的并行。
```

### ❌ 错误: 依次调用

```
# 不要这样:
调用 atlas-executor 处理子任务1
等待完成...
调用 atlas-executor 处理子任务2
等待完成...
```
